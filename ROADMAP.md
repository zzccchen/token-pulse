# Roadmap

These are priorities, not promised release dates. Suggestions are welcome in [feature requests](https://github.com/zzccchen/token-pulse/issues/new?template=feature_request.yml).

## Available now

Local Codex discovery, per-model completed-output statistics, a keyboard-accessible scatter plot, local history/CSV, tray and window entry points, English/Chinese UI, and light/dark themes. See [compatibility](docs/compatibility.md) for tested environments and limits.

## Next priorities

1. **Make first use easier.** Verify clean-machine Windows behavior and finish standalone distribution requirements before offering executable downloads.
2. **Broaden desktop evidence.** Record native Linux tray behavior by distribution, desktop, display server, and Qt version.
3. **Keep adapters trustworthy.** Add synthetic fixtures for new Codex formats; show useful diagnostics when evidence is incomplete.
4. **Improve usability.** Address reproducible accessibility, layout, translation, and recovery-progress issues.
5. **Measure overhead.** Publish reproducible idle/active collection measurements before setting resource targets.

## Later, if justified

Other local clients, remote collection, and cost estimates need separate designs and evidence sources. Changing Codex configuration or modes is outside the current read-only scope. No framework is being built in anticipation of these features.

A useful proposal explains the user's problem, the evidence available to solve it, and how it preserves local privacy and measurement semantics.
